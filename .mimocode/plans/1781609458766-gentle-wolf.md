# audio-relay-rs 代码优化计划

## 项目概述
Rust 实现的 PC-手机实时音频串流工具，通过 WebSocket 传输 PCM 音频数据。

---

## 优化项

### 1. 删除死代码和重复代码

| 文件 | 改动 |
|------|------|
| `src/utils/mod.rs` | 删除整个文件 |
| `src/main.rs` | 移除 `mod utils;` |
| `src/protocol/mod.rs` | 删除 `to_json_bytes()` 方法 |
| `src/audio/resampler.rs` | 删除 `source_rate()` 和 `target_rate()` 方法 |

### 2. 修复客户端 Ping 心跳无效 bug

**文件**: `src/client/mod.rs:132-137`

`ping_handle` 只做 interval tick 但从未发送 Ping 消息。修复为实际发送 `Message::Ping`，并在接收端处理 Pong 计算延迟。

### 3. 音频传输协议：JSON → 二进制帧

**问题**: 每帧音频用 JSON 序列化，PCM 二进制数据在 JSON 中被编码为数字数组（如 `[72, 101, 108, ...]`），开销约 3 倍，且解析慢。

**方案**: 音频数据改用 WebSocket 二进制帧（`WsMessage::Binary` / OkHttp `ByteString`），格式：
```
Offset  Size   Field
0       8      sequence (u64 LE)
8       8      timestamp (u64 LE)
16      4      sample_rate (u32 LE)
20      N      pcm_data (raw bytes)
```
控制消息（Hello/HelloAck/Ping/Pong 等）保持 JSON 文本帧不变。

**Rust 改动**:
- `src/protocol/mod.rs` — 新增 `encode_audio_frame()` 和 `decode_audio_frame()`
- `src/server/mod.rs` — Speaker 发送用 `WsMessage::Binary`，Microphone 接收解析二进制帧
- `src/client/mod.rs` — Speaker 接收解析二进制帧，Microphone 发送用 `WsMessage::Binary`

**Android 改动**:
- `AudioRelayService.kt` — 新增 `onMessage(webSocket: WebSocket, bytes: ByteString)` 回调，解析二进制帧头 + 写入 AudioTrack
- 删除 `playAudio(dataArray: JSONArray, sequence: Long)` 中的 JSONArray 逐字节遍历

### 4. 移除无用的 AudioDataAck

**文件**: `src/server/mod.rs:334-340`

服务端为每帧音频回复 `AudioDataAck`，但客户端从不处理。删除发送代码。

### 5. 消除音频热路径上的不必要分配

**文件**: `src/audio/capture.rs`
- `capture_windows()`: 逐字节 `VecDeque::pop_front` 填充 → 改为 `VecDeque::drain` 或直接 slice 复制
- `convert_to_i16_pcm()`: 每次创建新 Vec → 改为 `&mut Vec<u8>` output buffer 复用
- `float_to_i16_bytes()`: 同上

**文件**: `src/audio/playback.rs`
- `i16_bytes_to_float()`: 每次创建新 Vec → 改为 output slice

**文件**: `src/audio/resampler.rs`
- `resample()`: output Vec 每次重新分配 → 预分配复用

### 6. 改善播放端回调锁竞争

**文件**: `src/audio/playback.rs:38-58`

当前 `Arc<Mutex<mpsc::Receiver>>` 在每个 cpal 音频回调中获取锁。改用 `crossbeam::channel::bounded`，回调中 `try_recv()` 无锁/低锁。

**Cargo.toml**: 添加 `crossbeam-channel = "0.5"`

### 7. 修复 Web Server 的 unwrap panic

**文件**: `src/server/mod.rs:410-411`

`start_web_server` 中 `unwrap()` 会 panic。改为返回 `Result`，由调用方处理。
